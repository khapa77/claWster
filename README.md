## Обзор

Платформа принимает данные от клиентов, обрабатывает их на 48 ARM-ядрах (Odroid-MC1 x12) и возвращает результат. Подходит для batch-аналитики, ETL-пайплайнов, ML inference и обработки потоковых данных.

## Порог входа

**Оценка: высокий**

| Что нужно | Детали |
|-----------|--------|
| Железо | Уже есть: MC1 x12, HC1, RPi4 |
| ПО | Spark/Ray, MinIO, Kafka — требуют настройки под ARM |
| Знания | Distributed systems, Spark/Ray API, data engineering |
| Время до MVP | 4–8 недель |
| Стартовый капитал | Минимальный по железу, но нужны компетенции или найм |

Сложность в том, что нужно:
- Собрать/адаптировать Spark/Ray под ARM32/ARM64
- Настроить управление job-очередями
- Реализовать изоляцию задач между клиентами
- Обеспечить SLA по времени обработки

## Маржинальность

**Оценка: высокая**

| Статья | Детали |
|--------|--------|
| CAPEX | Железо (уже куплено) |
| OPEX | Электричество, интернет, поддержка |
| Средний чек | $50–500 за job или $200–2000/мес по подписке |
| Точка безубыточности | 5–10 активных клиентов |
| Потолок маржи | Высокий — вычисления продаются дорого |

ARM-архитектура даёт ~3x выигрыш по энергоэффективности против x86. При тех же OPEX — выше маржа.

**Пример расчёта:**
- Обработка 100GB данных = 2 CPU-часа × 48 ядер = ~96 ядро-часов
- Цена: $0.02/ядро-час → $1.92 за задачу
- x86 аналог (AWS EMR): ~$5–15 за ту же задачу

## Конкуренция

**Оценка: низкая (ARM-ниша)**

| Конкурент | Слабость |
|-----------|----------|
| AWS EMR / Glue | Дорого ($5–50/час), избыточно для малых объёмов |
| Google Dataflow | Vendor lock-in, сложная конфигурация |
| Azure HDInsight | Дорого, только x86 |
| Self-hosted Spark | Нужен собственный сервер и DevOps |

**Наши преимущества:**
- ARM → низкое энергопотребление → конкурентная цена
- Нет vendor lock-in (S3-совместимый MinIO)
- Персональный саппорт и SLA
- Возможность обработки данных в закрытом контуре (data privacy)

## Архитектура

```
Internet / Client
      │
      ▼
[RPi4 4GB] ── Job Coordinator (Ray Head / Spark Master)
      │         API Gateway, Job Queue (Kafka), MinIO Gateway
      │
[1Gb Switch]
      ├── [MC1 #01] ── Ray Worker / Spark Executor (4 cores)
      ├── [MC1 #02] ── Ray Worker / Spark Executor (4 cores)
      ├── ...
      ├── [MC1 #12] ── Ray Worker / Spark Executor (4 cores)
      └── [HC1]     ── MinIO (S3 storage), результаты job'ов

Lifecycle задачи:
Client → upload data (MinIO) → submit job (API) →
Kafka queue → Ray/Spark picks up → processes on MC1 nodes →
result → MinIO → Client downloads
```

**Потоки данных:**
- Входные данные: загрузка через S3 API (MinIO на HC1)
- Обработка: распределяется по MC1 нодам
- Результаты: сохраняются обратно в MinIO, клиент получает ссылку

## Стек технологий

| Компонент | Технология | Назначение |
|-----------|-----------|------------|
| Compute engine | Apache Spark или Ray | Распределённые вычисления |
| Хранилище | MinIO | S3-совместимое объектное хранилище |
| Очередь задач | Apache Kafka | Асинхронная обработка job'ов |
| Job scheduling | Airflow / Prefect | Планирование и оркестрация пайплайнов |
| API | FastAPI (Python) | REST API для отправки задач |
| Мониторинг | Prometheus + Grafana | Метрики job'ов и нод |
| Логи | Loki | Логи выполнения задач |
| Автоматизация | Ansible | Деплой воркеров на MC1 ноды |
